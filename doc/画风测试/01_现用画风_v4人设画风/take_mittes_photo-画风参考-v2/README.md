# take_mittes_photo 固定画风与已定规则 v2

用户于 2026-10-17 认可 v4 人设画风，并认可其蛋糕、拿铁、雨后落叶、斜挎包跨场景测试，明确“就固定这个画风”。

## 固定基准

实际 PNG 是画风依据，不能只依靠“二次元”“平涂”等词重新解释。00 为主基准，01—04 为相应主体的补充。每次按内容选相关图，不把全组默认一起传入。复制自原始生成结果，SHA-256 与来源见 references.json。

继承线条、色彩及阴影处理、细节密度；不继承图中手势、姿势、人物位置、服装、主体物件、构图或光照。衣柜设定图另作衣物款式参考，人设原图另作外貌参考。生成的新图片不自动顶替已认可基准。

## 使用时机与内容

- 日常私聊以文字为主，不给每次主动联系自动附图。用户明确想看，或上下文中的“看看”等确实指向可拍的环境、物件、穿搭时，再拍照。
- 原有 topic 保持现状，私聊主动聊天与拍照是分开的流程。topic 不是拍照的必要前提。
- 只表现 Mittes 亲手用手机能拍出来的生活内容：环境、食物、物件、穿搭和合理的身体局部。排除游戏画面、屏幕截图和手机界面。
- 用请求时刻的日程、当前地点和衣柜确定事实，不随意换装或虚构经历。一个日程时段中尚未发生的事情不能当作已经发生。测试假想情境应明确标注，不能反写真实日程。

## 取景与人物

- 根据用户要看的对象选择取景，只展示对本次分享有用的范围。穿搭和身体尤其需要收紧，不能默认交代整身或完整上半身；环境与物件也不机械扩展成场景全貌。
- 不规定固定角度。镜拍、俯拍等是可选例子，不固化成所有图片的模板。参考图中的“手放裙上”等姿势不能变成统一构图。
- 镜头关系须符合本人持机。镜自拍可以，不能无缘无故变成第三方给她拍照。画面不强制加入手机、手、头发或身体以证明拍摄者是谁。
- 无可见人脸，包含镜面、玻璃等反射及画中画。可以有头发、头部外轮廓和身体局部；若头部进入画面，脸必须完整裁出或实际遮住。不允许结构异常的头脸、用头发勉强遮住五官但留下错误脸型、凭空扭曲的颈部。
- 银白长发、浅樱粉内层与发梢等身份特征遵循原始人设和文字设定，仅在相关区域入镜时呈现，不为展示身份而硬加入头发。
- 用户修正后的发型偏好：平时基本双马尾，女仆装为扎牢的双马尾；洗浴、睡前等特殊场景根据活动整理头发，例如浴后包起。不要默认披发，也不是要求每种场景都双马尾。
- 猫耳、猫尾、铃铛是道具，依实际佩戴情况出现，不作为固定身体特征。

## 生成与记录

产品后端选择 CPA 生图接口；参考图支持实际传入。流程为解析用户想看的对象、冻结事实快照、规划取景、选择相关参考、生图、检查、发送；发生失败不能假装已有照片。生成过程和最终图在 mittes-panel 相机板块记录。

本组图片均由内置 image_gen 进行画风测试。固定画风的用户认可不等于 CPA 管线已验证；部署新基准时仍需更新相机参考选择与相关提示词，并验证实际生成效果。

## 当前接入状态

本目录完成已定画风与规则的归档；没有修改插件或线上配置。线上目前仍是 photo-style-v1 及旧提示词，衣柜部分发型也仍有披发旧写法，新规则尚未全部接入。

不采用的历史候选不作为参考：v1 全身/大片穿搭、v2 过度精细、v3 过度简化、v5 中头脸结构异常与露出侧脸的版本。它们仅保留为比较记录。
